# Device capacity read adapter v1 (default runtime HTTP disabled)

The Insights LibreNmsProvider exposes explicit getDeviceCapacityPage(deviceId, resourceType, options). resourceType is processor, mempool or storage; deviceId is a positive safe numeric LibreNMS ID. options contains only numeric page (default1/max100000), pageSize (default10/max20) and optional AbortSignal. No call is made by construction, the default collector, main or any existing HTTP route. This does not implement upload, CMDB mapping or a Center read model.

The adapter reads the source-local fixed GET /api/v0/devices/{id}/health/{type} directory, sorts distinct numeric sensor_id values and reads only the requested page's /{sensor_id} details. Each detail must have the same device_id and matching type_id. Directory max100; max21 HTTP calls/page, sequential; total deadline <=10s (the existing provider's stricter timeout wins), per-response1MiB and cumulative2MiB. Only HTTP(S) configured root origin, no embedded credentials/query/fragment, no redirects. JSON status=ok/graphs is required. Missing or malformed data is not silently empty; no source error body is exposed. Rejected response streams are cancelled.

Result contains schema_version=1, device_id, resource_type, page, page_size, total, coverage=page, snapshot_consistency=unverified, null observed_at/received_at and items. Each item has local id, generated generic label and fields. No raw descriptions, OIDs, model object or credentials. total belongs to that directory response, not a stable cross-page snapshot. Each item has the prior closed nine-key field DTO. This source adapter is not the complete Draft014 asset response.

capacitySourceProfile defaults to null. Only an operator-approved hrstorage-normalized-v1 profile plus matching hrstorage source fields can yield absolute bytes. Approval MUST follow a real source-version/hash audit such as the parent workspace probe; this config label is not independent proof of unchanged source code and cannot come from a browser/raw row. Unknown profile/vendor/OID/index/multiplier keeps bytes null/unit_unverified, while valid independent percentage may remain. Never multiply model totals by precision/storage_units again. Byte values must be safe integers with exact used+free=total (stricter than the diagnostic floating tolerance), positive total and consistent optional percentage; invalid values/relations are read_failed/contract_violation. Real zero usage is preserved.

Resource observation/receipt times remain null. Known values are partial/source_field_absent, never fresh/available from request time. CPU only provides usage_percent; core_count/thread_count/frequency_hz remain not_collected. Monitors are not physical cores, memory pools/volumes must not be summed into installed memory/disks. No names/CPU model are invented. This is a monitoring read, not metric remote_write or a third upload plane.

Credentials must be supplied through the site's approved server-side configuration. Fixed GET client behavior does NOT make LibreNMS's native user/API Token a globally read-only credential. No long-term identity is created, no previously exposed Token is reused, and no plaintext is saved or logged. Default runtime wiring and approved source credentials remain explicit deployment concerns; do not expose this adapter as an unauthenticated endpoint. Existing LLDP placeholder, unique Uplink spool and Center contracts are unchanged.

## Explicit service HTTP boundary

createCapacityHttpServer from src/capacity-http.mjs is opt-in construction only; main and collectors do not register it. It requires an explicit >=32-character service token, a nonempty server-owned numeric device allowlist and a provider exposing getDeviceCapacityPage. Bind only on loopback for the current preview. GET /api/v1/monitoring/devices/{numeric-id}/capacity/{processor|mempool|storage} accepts only page (default1/max100000) and pageSize (default10/max20); duplicates, caller tenant/source/identity claims and unsupported types are rejected before provider I/O. Other devices and aliases are404, missing service identity401, writes405, invalid query400; no anonymous fallback. Replies no-store, <=256KiB with sanitized errors, a <=10-second abort deadline and client-disconnect cancellation. Service authentication is not Portal user delegation or a production native read-only token guarantee.
